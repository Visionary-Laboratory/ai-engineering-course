Transformer 模型

Transformer Models

自注意力 / 01

本讲路线：搭建 Transformer

从自注意力出发，依次学习编码器、解码器、编码器—解码器结构，再扩展到语言、视觉与混合专家模型。

自注意力 / 02

自注意力：由内容决定信息聚合

输入表示分别投影为 Query、Key 和 Value。Query 与各 Key 的匹配分数决定当前位置应聚合哪些 Value；同一序列中的位置因此能够直接交换信息。

Attention⁡(Q,K,V)=softmax⁡ ⁣(QK⊤dk)V\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)VAttention(Q,K,V)=softmax(dk​​QK⊤​)V

Softmax 沿被关注的位置归一化。从单个位置的计算展开到矩阵运算；下方实验对应“打分—归一化—加权求和”三步。

自注意力 / 03

多头注意力：多个投影子空间

多头注意力使用多组投影并行计算注意力，再拼接各头结果并进行输出变换。不同头可以形成不同的信息聚合方式。

指代关系可以帮助理解远距离关联。阅读注意力图时，先确认横纵轴代表查询还是被查询位置，再看颜色如何对应权重。

自注意力 / 04

为序列加入位置信息

仅依赖内容的自注意力本身不直接区分序列顺序。位置编码或位置相关机制为模型提供顺序信息，使相同词在不同位置能够产生不同作用。

需要区分内容表示与位置表示，以及位置如何进入注意力计算。

自注意力 / 05

与 CNN、RNN 的结构比较

CNN 使用局部连接和共享核，RNN 按时间传递状态，自注意力则通过内容相关权重连接序列位置。它们对信息路径、并行方式与计算成本作出了不同选择。

对标准全局注意力，长度为 nnn 的序列需要形成 n×nn\times nn×n 的关联矩阵。更直接的信息交流也带来了随长度增长的存储与计算成本。

编码器 / 06

编码器

将注意力、前馈网络、残差连接与归一化组成可堆叠的模块。

编码器 / 07

Transformer 编码器的组成

编码器层通常包含多头自注意力与逐位置前馈网络，并配合残差连接和 LayerNorm。注意力负责位置间的信息交流，前馈网络在各位置上变换特征。

进一步比较 Pre-LN 与 Post-LN：归一化位于子层之前或残差相加之后，会改变计算路径与训练特性。最后对照 BatchNorm 和 LayerNorm 的统计维度。

解码器 / 08

解码器

从逐词生成的例子出发，理解因果掩码与自回归生成。

解码器 / 09

解码器如何逐步生成序列

解码器根据已有上下文预测下一个 token，再把新 token 纳入后续上下文。逐步展开的中文例子可以直观展示这一过程。

一次预测得到的是词表上的分布，如何从分布中选出具体 token 属于解码策略。网络计算与选择策略应分别理解。

解码器 / 10

因果掩码与自回归建模

因果掩码阻止当前位置关注未来位置，使训练时的信息条件与“由过去预测未来”的目标一致。

自回归分解可写为 p(y)=∏tp(yt∣y<t)p(y)=\prod_t p(y_t\mid y_{<t})p(y)=∏t​p(yt​∣y<t​)。比较自回归与非自回归方式：它们在输出依赖、生成步数和建模选择上有所不同。

编码器—解码器 / 11

编码器—解码器

把源序列编码与目标序列生成连起来，加入跨注意力与训练目标。

编码器—解码器 / 12

跨注意力连接输入与输出

在编码器—解码器结构中，解码器既关注已有目标序列，也通过跨注意力访问编码器输出。跨注意力的 Query 来自解码侧，Key 和 Value 来自编码侧。

训练使用源序列与目标序列配对计算预测损失。沿结构图区分三处注意力：编码器自注意力、解码器带掩码自注意力、编码器—解码器跨注意力。

编码器—解码器 / 13

在 Transformer 上进行束搜索

模型为每个候选前缀输出下一词分布。束搜索扩展候选、累计序列分数，再只保留固定数量的候选继续生成。

沿搜索树逐步观察候选扩展和剪枝。留意序列分数是整条路径的累计结果，而不是只看最后一个 token 的概率。

编码器—解码器 / 14

采样、训练技巧与生成评价

采样允许从预测分布中选择不同结果；搜索则倾向寻找高分序列。两者适合的目标不同，需要结合生成任务决定。

第 79–81 页介绍 BLEU：比较候选译文与参考译文的 n-gram 匹配，并对过短的译文施加长度惩罚；随后讨论如何优化序列级评价目标。

第 82–83 页讨论 Exposure Bias 与 Scheduled Sampling，区分训练时的真实历史和推理时模型生成的历史。第 84 页回到 Transformer 整体结构作小结。

模型家族 / 15

Transformer 模型家族

沿语言模型与视觉模型两条应用线，比较同一基本结构的不同组织方式。

模型家族 / 16

BERT、T5 与 GPT

BERT 以编码器结构构造上下文表示；T5 使用编码器—解码器框架组织文本到文本任务；GPT 使用带因果约束的解码器结构建模序列。

这些模型的区别涉及结构、可见上下文与训练目标。进一步考虑 Decoder-only 的选择；理解时应把任务需要与结构带来的计算方式联系起来。

模型家族 / 17

ViT：把图像转换为 token 序列

ViT 将图像切成 patch，展平并线性投影为嵌入，再加入位置信息。分类版本加入可学习的 class token，用其输出作为图像表示。

之后，patch token 序列进入 Transformer 编码器。逐步观察 patch embedding、position embedding、class token 和编码器之间的关系。

模型家族 / 18

ViT 的计算量、结果与局限

深度、隐藏维度、MLP 宽度、头数与 patch 大小共同影响模型。patch 越小，在固定图像分辨率下 token 数越多，全局注意力矩阵也越大。

ViT 的实验也揭示了固定尺度 token 与高分辨率密集预测的困难。实验结果应连同预训练数据规模和设置解读。

模型家族 / 19

Swin：层级结构与移位窗口

Swin 通过局部窗口注意力限制一次交互的范围，并用移位窗口建立跨窗口联系。Patch merging 逐步降低空间分辨率、增加通道，形成层级表示。

依次检查整体架构、patch merging、Swin block、窗口划分、移位窗口、相对位置偏置及模型规格。最后的性能表用于比较给定实验条件下的结果。

混合专家 / 20

混合专家模型

从专家与路由的基本概念出发，逐步讨论稀疏计算、负载均衡和专家容量。

混合专家 / 21

MoE：让输入选择部分专家

混合专家模型包含多个专家网络，以及决定如何组合专家输出的门控或路由机制。稠密 MoE 可以计算多个专家再加权，稀疏 MoE 只激活其中少数专家。

这样可以增加总参数容量，同时控制每个 token 实际使用的计算。总参数量、激活参数量和计算量是不同概念；“专家”也不意味着天然对应人为定义的某个领域。

混合专家 / 22

MoE 放在哪里，路由如何选择

典型做法是在部分前馈子层使用专家网络，由路由器为 token 分配专家。路由既影响模型表达，也影响计算分配与通信。

观察路由示意时，分别统计每个 token 选择了多少专家，以及每个专家接收了多少 token。这两个方向的分配约束并不相同。

混合专家 / 23

Top-k 路由与负载均衡

Top-k 路由只保留分数较高的少数专家。Token choice 从 token 侧选择专家；其他路由方式可从专家接收 token 的角度组织分配。

若大量 token 集中到少数专家，会出现利用不均与容量压力。辅助损失等机制用于鼓励更均衡的分配，但也需要平衡主任务目标与路由约束。

混合专家 / 24

专家容量与路由训练策略

专家容量限制一个批次中每个专家可接收的 token 数量。容量太小可能导致溢出处理，容量较大会增加预留计算或存储。Switch Transformer 的示例将这些问题联系起来。

路由策略包括辅助损失、DeepSeek 系列的路由设计、偏置调整与随机性等。重点比较这些方法如何影响选择概率、负载和训练稳定性。

混合专家 / 25

阅读 MoE 模型与消融结果

DeepSeek 与 OLMoE 提供了混合专家模型的消融实验案例。消融实验通过改变某个设计，帮助判断该设计在给定设置中的作用。

比较结果前先核对参数规模、训练预算、激活专家数和评价任务。各组实验对应特定训练设置，不能直接视为统一的模型排名。

混合专家 / 26

视觉中的混合专家：V-MoE

专家机制也可以用于视觉模型。图像 patch 作为 token 进入路由，不同 token 可以被送到不同专家，形成条件计算。

沿 V-MoE 的结构和实验图，观察路由粒度、激活专家数量及计算预算之间的联系。视觉 token 的数量同样会影响专家负载。

混合专家 / 27

以 Mixtral 回顾稀疏模型的成本

以 Mixtral 为例，区分总参数量与每个 token 的激活参数量。稀疏激活节省的是部分前向计算，不会自动消除全部参数存储和专家间通信。

回看本讲：自注意力决定信息如何在位置间流动，MoE 则进一步决定哪些参数参与当前输入的计算。
